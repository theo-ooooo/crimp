# 크루 개설/가입 기초 기획 — v0.1

PRD §6.2 "크루 개설/가입 (지역·수준·스타일별)" 의 Phase 1.5 최소 범위.

작성일: 2026-05-08. 베타 후 활성화할 커뮤니티 진입점으로, 피드의 친구/내 암장 관계를 보완한다.

---

## 1. 의도

**문제**: 현우는 자주 가는 암장과 비슷한 레벨의 사람을 찾고 싶지만, 오픈채팅·인스타·암장 게시판으로 정보가 흩어져 있다. 지수는 입문자 모임을 찾고 싶지만 크루 분위기와 난이도를 알기 어렵다.

**목표**:
1. 사용자가 지역·암장·레벨·스타일로 공개 크루를 탐색한다.
2. 크루장은 앱 안에서 크루를 만들고 기본 정보를 관리한다.
3. 사용자는 가입 요청을 보내고, 크루장은 승인/거절한다.
4. 가입한 크루는 프로필/피드 확장의 기반 데이터가 된다.

**비목표 (v0.1 제외)**:
- 크루 채팅, 게시판, 회비/결제.
- 파트너 매칭 자동 추천.
- 초대 링크, 비공개 크루 검색 숨김, 운영자 신고/제재 콘솔.

## 2. 사용자 경험

### 2.1 크루 찾기

**진입점**:
- App: BottomTabs `Crew` 탭.
- Web: `/crews` 목록.

**목록 필터**:
- 지역: 시/구 텍스트 또는 mainGym 기반 추천.
- 암장: `mainGym` 또는 검색된 gym.
- 레벨: `BEGINNER`, `INTERMEDIATE`, `ADVANCED`, `ALL`.
- 스타일: `BOULDERING`, `LEAD`, `BOTH`.

**카드 정보**:
- 크루 이름, 대표 지역, 대표 암장.
- 멤버 수 / 정원.
- 레벨·스타일 chip.
- 가입 방식: 승인제 (`APPROVAL`) 우선.

### 2.2 크루 상세

**상단 정보**:
- 이름, 소개, 대표 지역/암장, 레벨, 스타일, 멤버 수.
- 크루장 닉네임.

**CTA**:
- 비회원: "가입 요청".
- 요청 대기 중: "요청 취소".
- 멤버: "내 크루".
- 크루장/관리자: "가입 요청 관리", "정보 수정".

### 2.3 가입 요청

가입 요청 본문은 선택 입력으로 둔다.

```json
{
  "message": "주 2회 강남권에서 V4~V5 등반합니다."
}
```

정책:
- 한 사용자는 같은 크루에 동시에 1개의 `PENDING` 요청만 가질 수 있다.
- 이미 멤버면 요청 불가.
- 정원이 찬 크루는 요청 불가.
- 크루장이 승인하면 `crew_members` 행을 만들고 요청 상태를 `APPROVED` 로 바꾼다.

### 2.4 모임

모임은 크루의 하위 기능이 아니라 독립 탭에서 접근한다.

- BottomTabs: `홈 / 피드 / 세션 / 모임 / 크루 / 프로필`.
- 암장 탭은 footer 에서 제외하고, 홈의 "암장 찾기" 또는 모임 장소 선택 단계에서 `GymSearch/GymDetail` 화면으로 접근한다.
- 모임은 `crew_id` 없이 생성할 수 있다. 특정 크루 상세에서 만든 모임만 `crew_id` 를 연결한다.
- 모임 만들기는 한 화면 입력폼이 아니라 `기본 정보 → 날짜/시간 → 장소 → 확인` 단계형 플로우로 진행한다.
- 장소는 암장 검색 화면에서 선택하는 것을 기본으로 하고, 암장 외 장소는 텍스트 위치로 보완한다.
- 모임 상세에서는 장소·일시·소속 크루·참여 현황을 확인하고 바로 참여 또는 승인 요청을 보낸다.
- 모임 참여 방식은 `OPEN`(바로참여) 과 `APPROVAL`(승인제) 두 가지다. 승인제 모임은 요청 메시지를 함께 받아 `PENDING` 으로 보관한다.
- 모임 생성자는 생성과 동시에 `ACTIVE` 참여자로 자동 등록된다.
- 모임 생성자는 해당 모임의 방장이다. 독립 모임은 방장만 관리하고, 크루 모임은 방장과 크루 `OWNER`/`ADMIN` 이 관리한다.
- 모임 관리자는 시작 전 모임의 설명·일시·장소·정원·참여 방식을 수정하거나 모임을 취소할 수 있다.
- 승인제 모임의 요청 목록은 모임 관리자만 확인하며, 요청 메시지를 보고 승인/거절한다. 승인 시 정원을 재확인한다.
- 사용자 화면에서는 "삭제"보다 "모임 취소"로 표현한다. 내부 구현은 `deleted_at` soft-delete 를 사용한다.

## 3. MVP 범위

### 3.1 기능

| 구분 | 포함 |
| --- | --- |
| 크루 생성 | 이름, 소개, 대표 이미지, 대표 지역, 대표 암장, 레벨, 스타일, 정원 |
| 크루 수정 | 크루장/관리자만 기본 정보와 대표 이미지 수정 |
| 크루 탐색 | 공개 크루 목록, 필터, 커서 페이지네이션 |
| 크루 상세 | 기본 정보, 대표 이미지, 멤버 수, 내 가입 상태, 예정 모임 |
| 가입 요청 | 생성, 취소, 크루장 승인/거절 |
| 멤버 관리 | 크루장/관리자/멤버 역할, 본인 탈퇴 |
| 모임 | 전역 모임 목록, 모임 상세, 참여/요청/취소, 참여자 목록, 승인 요청 관리, 모임 관리자 수정/취소, 독립 모임 생성, 크루 상세 예정 모임 목록, 단계형 생성 플로우 |

### 3.2 제외

- 크루 feed 별도 타임라인.
- 크루 공지/게시글.
- 크루 멤버 강제 추방 UI (API 는 후속).
- 추천 랭킹. v0.1 은 `created_at DESC` + 필터만 사용.

### 3.3 대표 이미지·모임

- 대표 이미지는 기존 미디어 업로드 플로우로 `usage=CREW` READY IMAGE 를 만든 뒤 `crews.image_media_id` 에 연결한다.
- 목록/상세 응답은 `imageMediaId`, `imageUrl` 을 포함한다. CDN base URL 이 없거나 variant 가 없으면 `imageUrl=null` 로 내려간다.
- 모임 v0.1 은 `title`, `startsAt`, `joinPolicy`, 선택 `description/crew/gym/location/capacity` 를 저장한다.
- 모임 참여는 `meetup_participants` 로 관리한다. `OPEN` 은 즉시 `ACTIVE`, `APPROVAL` 은 요청 메시지와 함께 `PENDING` 이며 사용자는 본인 참여/요청을 취소할 수 있다. 모임 생성자(`meetups.created_by`)는 방장으로 취급한다.
- 모임 관리자는 `PENDING` 요청을 승인/거절한다. 댓글, 알림은 후속 범위다.

## 4. 정책

### 4.1 공개 범위

v0.1 은 `PUBLIC` 크루만 노출한다. 비공개/초대제 크루는 테이블 enum 여지를 남기되 UI/API 에서 생성하지 않는다.

### 4.2 권한

| 액션 | 권한 |
| --- | --- |
| 크루 생성 | 로그인 사용자 |
| 크루 수정 | `OWNER`, `ADMIN` |
| 가입 요청 승인/거절 | `OWNER`, `ADMIN` |
| 멤버 목록 조회 | 로그인 사용자 (PUBLIC 크루) |
| 멤버 탈퇴 | 본인, 단 `OWNER` 는 마지막 owner 이면 탈퇴 불가 |

### 4.3 탈퇴 사용자

사용자 계정 탈퇴 시:
- `crew_members` 는 유지하되 표시명은 공개 컨텐츠 정책과 동일하게 `탈퇴사용자` 로 익명화한다.
- 탈퇴 계정의 OAuth 연결은 다음 로그인 때 새 사용자로 재연결될 수 있어야 한다. 따라서 같은 소셜 계정으로 재가입한 사용자는 기존 탈퇴 계정의 `crew_members` 행에 막히지 않고 새 가입 요청을 보낼 수 있다.
- 탈퇴 사용자가 `OWNER` 인 크루는 운영 정책 필요. v0.1 구현 전까지 "마지막 owner 탈퇴 차단" 으로 단순화한다.
- `PENDING` 가입 요청은 취소 처리한다.

## 6. 의존 관계

- 프로필 `level_self` 편집이 열리면 크루 추천/필터 품질이 좋아진다. v0.1 에서는 선택 필터로 충분하다.
- mainGym 설정은 크루 탐색 기본 필터/추천 기준으로 사용한다.
- 알림 도메인이 생기면 가입 요청 승인/거절 알림을 연결한다. v0.1 은 요청 목록에서 polling 또는 수동 새로고침.
